# UI 风格一致性轻量检查清单

> 适用范围：所有涉及样式改动的 PR（CSS/SCSS、组件样式、布局、设计 token、UI 组件库升级）。

## 1) 必查项（轻量）

在提交前逐项确认：

- [ ] **间距层级**：同一页面内的外边距/内边距是否遵循统一梯度（建议优先使用 4/8 的倍数，如 8、12、16、24、32）。
- [ ] **字体层级**：标题/正文/辅助文字的字号、字重、行高是否稳定且有层级关系。
- [ ] **卡片圆角**：同类卡片与弹窗圆角是否统一（避免同页出现多个无规则半径）。
- [ ] **阴影强度**：阴影是否克制且与层级匹配（避免同层级阴影深浅不一致）。
- [ ] **边框对比**：边框与背景对比度是否足够但不过重（边界可辨识、不刺眼）。
- [ ] **移动端断点行为**：在移动视口下布局是否正常换行/折叠，无溢出、遮挡、重叠。

---

## 2) 固定截图位点（每次样式 PR 必做）

为保证可比性，以下页面必须按**固定视口**截图，并沿用同一命名规则。

### 固定视口

- **Desktop**：`1440 x 900`
- **Mobile**：`390 x 844`

### 页面位点

- Billing：`/#/billing`
- Invite：`/#/billing?tab=invite`
- Ticket：`/#/tickets`

### 截图命名与目录

统一放在：`artifacts/ui-style/<PR编号或分支名>/`

建议命名：

- `billing-desktop.png`
- `billing-mobile.png`
- `invite-desktop.png`
- `invite-mobile.png`
- `ticket-desktop.png`
- `ticket-mobile.png`

> 若页面需要登录，请使用测试账号登录后再截图，确保每次取景区域一致（首屏为主）。

---

## 3) 提交前检查命令（建议）

按顺序执行以下命令：

```bash
npm run lint
npm run build
```

若项目已有 E2E/截图脚本，也应补充执行并记录在 PR 中。

---

## 4) PR 记录规范（必须包含）

每个样式 PR 都必须记录：

1. **检查命令**（执行了什么）
2. **截图路径**（6 张固定截图的实际路径）
3. **结论**（是否通过、是否存在已知差异）

可直接复用 `.github/pull_request_template.md` 中的“UI 样式检查（必填）”区块。
